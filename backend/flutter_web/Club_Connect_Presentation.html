System Architecture & Data Flow

Bloom: Analyze
Step 1: ID Card Scan
Client Capture
  • Student holds physical card to device camera.
  • Captures linear barcode (Code 128).
  • Sends payload via secure REST POST.
Step 2: C++ Decode
Processing Engine
  • ZXing C++ decodes admission number.
  • Handles blur, tilt, and lighting glare.
  • Fallback to simulated college database.
Step 3: Portal Sync
Verification Layer
  • Extracts Name, Semester & Course.
  • Generates college-branded avatar.
  • Issues authenticated JWT token.
Step 4: Active Hub
Presentation Layer
  • Loads student profile card.
  • Shows clubs & upcoming fests.
  • Generates digital fest passes.
🗣️ Speaker Note: Walk through the 4-step pipeline: Student holds card → Barcode decoded → College database verifies Name and Semester → Student accesses their society dashboard.

Software Development Process (Agile Scrum)

Bloom: Apply
Waterfall Model (Why We Avoided It)
Rigid, Late Testing & High Risk
  • Strict Sequential Phases: Testing occurs only at the very end of the academic semester.
  • High Risk of Failure: If barcode scanning fails in week 12, the entire project misses evaluation.
  • Zero Early Feedback: Faculty cannot review working prototypes during mid-semester reviews.
  • Costly Fixes: Changing requirements late in development requires rewriting everything.
Agile Scrum Model (Our Approach)
Iterative, Flexible & Early Cloud Delivery
  • Sprint 1–2: Wireframing, database schema, and basic Django API endpoints.
  • Sprint 3–4: C++ ZXing barcode integration and GL Bajaj portal record mapping.
  • Sprint 5–6: Flutter Web UI polish, warm campus theme, and Render cloud deployment.
  • Working Software at Every Stage: Real URL ready for demonstration weeks before final viva.
🗣️ Speaker Note: Explain why we adopted Agile Scrum instead of Waterfall. Sprints allowed us to test barcode hardware early and deploy to the cloud weeks before the deadline.
